# Telco Customer Churn Prediction

Churn prediction pipeline for a telecom dataset — covers data cleaning, feature engineering, model training with cross-validation, and a REST inference endpoint.

Dataset: [Telco Customer Churn — Kaggle](https://www.kaggle.com/datasets/blastchar/telco-customer-churn)

---

## Running the Pipeline

### 1. Train

```bash
cd src
python train.py
```

This runs 4 model configurations with 5-fold stratified CV, tunes GradientBoosting with `RandomizedSearchCV`, evaluates on a held-out test set, and saves the best pipeline to `models/best_model.joblib`.

Training takes roughly 3–4 minutes.

### 2. Predict — CLI

```bash
# Uses sample.json from project root
python src/predict.py --input sample.json

# Inline JSON
python src/predict.py --json '{"customerID":"7590-VHVEG","gender":"Female",...}'

# No args — runs the built-in sample
python src/predict.py
```

### 3. Predict — API

```bash
uvicorn api.main:app --reload 
```

**Test with curl:**
```bash
curl -X POST http://localhost:8000/predict \
     -H "Content-Type: application/json" \
     -d @sample.json
```

**Interactive docs:** `http://localhost:8000/docs`

**Health check:** `http://localhost:8000/health`

## Model Results

All scores from 5-fold stratified CV on the training set (80% of data). Final row is the held-out test set — touched once, after all tuning was done.

| Model | ROC-AUC | F1 | PR-AUC |
|---|---|---|---|
| Logistic Regression (baseline) | 0.8451 ± 0.0118 | 0.6277 ± 0.0219 | 0.6593 ± 0.0153 |
| Random Forest (300 trees) | 0.8248 ± 0.0118 | 0.5426 ± 0.0261 | 0.6158 ± 0.0312 |
| GradientBoosting (default) | 0.8473 ± 0.0120 | 0.5813 ± 0.0241 | 0.6630 ± 0.0241 |
| **GradientBoosting (tuned)** | **0.8492 ± 0.0111** | **0.5809 ± 0.0192** | **0.6670 ± 0.0198** |
| Holdout test set | 0.8461 | 0.5870 | 0.6588 |

Best hyperparameters found: `n_estimators=100, max_depth=3, learning_rate=0.05, subsample=0.7, min_samples_leaf=20`



## Data Issues Found in EDA

**TotalCharges stored as string** — the column contains whitespace for 11 customers with `tenure = 0`. These are brand-new customers with no charges yet, so the missing values are filled with `0.0` rather than the column median. This is intentional.

**Class imbalance** — handled via `class_weight='balanced'` in Logistic Regression and `min_samples_leaf` tuning in GradientBoosting. No external resampling library required.

## Data Leakage Prevention

Everything that could leak test information into training is handled inside the scikit-learn `Pipeline`:

- `train_test_split` with `stratify=y` happens before any fitting
- `StandardScaler` and `OneHotEncoder` are fit only on training folds
- Cross-validation uses `StratifiedKFold` — class balance is preserved per fold
- The holdout test set is used exactly once, after all tuning is complete
- Feature engineering (`AvgMonthlyCharge`, `ServiceCount`, `HighRisk`) is stateless — no statistics derived from data
